# Quiver submission requirements

Checked against the authenticated production submission form on 21 October 2026 at https://quiverlauncher.com/submit.

The repository must be public on GitHub.com or GitLab.com when submitted. Quiver lists projects that can be built or downloaded from that public repository; the form does not explicitly require a binary release. A tested installable release remains this project's usability target.

The submitter must have personally installed and run the project and supply a screenshot of it working. The image must be PNG, JPEG, WebP or GIF, at most 5 MB, and should show identifiable app content or a window title. Projects shipping copyrighted game files are rejected and should ask players for their own copy.

The form includes repository URL, ported game selection, project name, optional author/team, porting method, original console, optional tags/icon/media, tested operating systems, developer status, AI-use classification, optional maintainer notes, and the installation/content confirmation. Porting method and console tags are supplied automatically. Up to three media links can be added. The displayed submission limits are three projects per day and five pending reviews. Maintainers review submissions before publication.

For this project select Game port, Static recompilation, Nintendo Entertainment System, and only operating systems actually tested. Its original integration has been written with substantial AI assistance, so the README and AI-use response should describe that accurately. Do not classify the work as human-only.

The prototype is not yet submitted. Complete the user-facing launch flow, package review and installation test before making the form's attestations. A private development repository must become public before this step.
